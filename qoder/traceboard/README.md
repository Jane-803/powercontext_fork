# 迹点 Traceboard

面向科研小组和项目协作的证据与进度工作台。把会议纪要、实验结果、阻塞和笔记归档到 seekdb，按项目、日期、类型与全文关键词联合检索；任务可以关联证据 ID；周报由实际记录生成，保留原始来源。

## 运行

依赖：seekdb 服务端、MySQL 命令行客户端、Python 3.9+。无需 Python 第三方包。先创建数据库：

```bash
mysql -h 127.0.0.1 -P 2881 -u root < schema.sql
```

若数据库有密码，设置 `SEEKDB_PASSWORD`；还可设置 `SEEKDB_HOST`、`SEEKDB_PORT`、`SEEKDB_USER`、`MYSQL_BIN`、`APP_HOST`、`APP_PORT`。随后运行：

```bash
python3 server.py
```

打开 `http://127.0.0.1:8088`。生产部署时需要给服务加身份认证和 HTTPS；本项目默认只监听本机。

## 验证样例

1. 当前项目填写 `科研项目 A`，新增一条类型为“成果”的记录，标题 `向量检索实验`，内容 `召回率提升到 0.86`，并附上来源链接。
2. 搜索 `召回率`。应出现刚保存的记录；切换类型为“会议”后应消失，切回“成果”后应恢复。此检索由 seekdb 的 `FULLTEXT` 索引和 SQL 条件共同完成。
3. 新增任务 `复核召回率`，设为进行中，关联刚才记录卡片上的证据 ID。
4. 打开周报，选择包含该记录日期的区间并生成。结果应包含记录、来源、任务状态和关联 ID。

如中文全文分词的单个词检索结果受版本或分词词典影响，可用完整标题 `向量检索实验` 复核；实际 SQL 见 `server.py` 的 `evidence_rows`。

## 网站与提交

`site/` 是应用前端资源，由 `server.py` 服务。Qoder Sites 若仅支持静态资源托管，不能直接提供 seekdb 后端；需另行部署后端并配置公开访问入口，或将 Sites 作为作品展示页。站点发布、公开可见范围、Qoder UID 和真实访问 URL 必须在 Qoder 中完成并核验，不能用本地页面 URL 代替。

`showcase/` 是可发布的静态作品展示页。当前页面包含界面示意，不是实际运行截图；正式提交前需补入真实截图或演示视频，并在无痕窗口验证公开访问。

项目位于 `powercontext_fork` 的 `2026-competition` 分支 `qoder/` 目录，仓库历史包含冻结基线 `9db1753434162c0aa7c9f1189a1722e617880a52`。`showcase/` 可作为 Qoder Sites 的静态站点源目录。使用 Qoder 完成后续主要开发过程并保留可核对的记录；当前这部分准备工作由 Codex 完成，不能声称为 Qoder 开发记录。
